Edit the contact on the left. The editor only accepts changes that keep the document valid for the schema, so try breaking it: shorten the name, enter a bad postcode, add a sixth tag or duplicate one. The schema uses every supported keyword, and each field’s hint names the keyword it demonstrates.

Where to find each keyword
Composition
allOf, anyOf and oneOf are under Composition and references (Entity, Preferred contact, pet). not is on username. if/then/else is on role (root) and Shipping.
Objects
properties, required, additionalProperties (root, labels, limits), patternProperties and propertyNames, minProperties/maxProperties (labels), dependentRequired, dependentSchemas and dependencies (Dependencies).
Arrays
items, uniqueItems, minItems/maxItems (tags), prefixItems (Location), tuple items with additionalItems (Legacy tuple), contains, minContains/maxContains (Milestones). The editor’s own tabular keyword shows an array of simple objects as a table: unset in Line items (a table when there is room), true in Phone numbers, false in Team.
Strings and numbers
minLength, maxLength, pattern and seven format values (Strings and formats); minimum, maximum, exclusiveMinimum, exclusiveMaximum, multipleOf (Numbers).
Values and metadata
type (including type arrays), enum (including mixed types), const (Entity’s kind), default, title, description.
References
$ref by pointer (address), by anchor (Preferred contact), to the root with # (referrals), and recursively (relatives), with $defs.

The same editor, pointed at a metaschema: a schema that describes the schemas SchemaEditor understands. Edit the Task schema on the left, or load the Contact schema into it. The Form tab turns whatever schema you build into a working editor, live. Pick a kind for each schema (string, object, array and so on), then add keywords from its menu. Keywords the editor doesn’t support are refused.
